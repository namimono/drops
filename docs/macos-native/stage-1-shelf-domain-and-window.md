# 阶段 1：内容架领域与窗口骨架

> 状态：待实施  
> 上级文档：[macOS 原生方案](README.md)  
> 前置阶段：[阶段 0：需求冻结与技术验证](stage-0-requirements-and-validation.md)

## 1. 阶段定位

本阶段建立内容架的领域规则和多窗口运行骨架，使应用具备稳定创建、展示、切换状态和关闭多个内容架的能力。重点是生命周期和窗口稳定性，不要求完成真实内容加入与媒体处理。

## 2. 实现目标

- 建立内容架、内容项、选择状态和生命周期的统一模型。
- 支持主动创建与拖拽触发两种不同生命周期。
- 支持多个内容架相互独立地存在、变化和关闭。
- 完成空态、收起态、展开态的窗口骨架及基本状态转换。
- 将窗口数量、屏幕边界和迟到事件处理固化为可测试规则。

## 3. 范围

### 3.1 本阶段包含

- 内容架及其生命周期、状态和选择模型。
- 内容架管理、窗口创建、窗口定位和关闭。
- 快捷键与菜单栏创建入口的基础链路。
- 主动创建、临时创建、晋升和自动关闭的状态能力。
- 空态、收起态、展开态的界面骨架。
- 最多 20 个内容架的限制和反馈。

### 3.2 本阶段不包含

- Finder 真实拖入、剪贴板落盘和内容拖出。
- 文件缩略图、Quick Look、文本合并和完整右键菜单。
- 正式视觉动画和完整设置页面。
- 图片或视频处理能力。

## 4. 阶段交付物

- 可测试的内容架领域模型与生命周期规则。
- 多窗口管理和系统入口骨架。
- 空态、收起态、展开态界面骨架。
- 生命周期、数量限制和迟到事件的自动化测试。
- 多屏与屏幕边缘下的窗口位置验收记录。

## 5. 验收标准

| 编号 | 验收标准 | 验收证据 |
|---|---|---|
| S1-01 | 通过快捷键和菜单栏入口均可在鼠标所在屏幕附近创建一个持久内容架。 | 入口演示与系统测试 |
| S1-02 | 每个内容架拥有独立标识、状态和窗口；修改或关闭一个内容架不影响其他内容架。 | 多窗口自动化测试与演示 |
| S1-03 | 第 20 个内容架允许创建，第 21 个被拒绝，并向用户提供明确反馈。 | 边界测试 |
| S1-04 | 主动创建的空内容架不会因失焦或短时间无操作自动关闭，只能由用户明确关闭或退出应用。 | 生命周期测试 |
| S1-05 | 临时内容架具备“等待接收、接收后晋升、未接收后关闭”的可测试状态转换，阶段内允许通过模拟事件验证。 | 领域单元测试 |
| S1-06 | 内容架可在空态、收起态和展开态之间稳定切换，快速重复操作不会卡在中间尺寸或失去响应。 | 重复操作测试与演示 |
| S1-07 | 窗口圆角、阴影和透明区域显示正常，不出现灰色直角底层、异常描边或背景穿透。 | 浅色/深色模式截图 |
| S1-08 | 在多显示器、不同缩放比例和屏幕边缘创建时，窗口主体保持在可见工作区内。 | 多屏验收记录 |
| S1-09 | 窗口关闭后，来自旧窗口或旧生命周期的迟到事件被安全忽略，不导致崩溃或错误复活。 | 自动化测试与异常日志检查 |
| S1-10 | 20 个空内容架同时存在时仍可完成创建、展开、收起和关闭，且无持续异常 CPU 占用。 | 基础性能与稳定性记录 |

## 6. 准入条件

- 阶段 0 的所有退出条件已满足。
- 窗口类型、不抢焦点策略和最低支持系统已确定。
- 原生工程和测试 Target 可持续构建。

## 7. 退出条件

- S1-01 至 S1-10 全部通过。
- 内容架生命周期和数量限制已有自动化测试保护。
- 多窗口骨架可以承载阶段 2 的真实拖放与剪贴板内容。
- 不存在窗口无法显示、状态转换卡死或关闭后访问无效引擎等阻断问题。

## 8. PRD 映射与后续依赖

本阶段主要覆盖 PRD 5.1“内容架的创建与关闭”、7.1“内容架状态”和 9.5“多内容架与系统入口”的窗口部分。阶段 2 在此基础上接入真实数据与拖拽会话，不重新定义生命周期。
